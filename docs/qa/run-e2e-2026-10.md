# Run page — end-to-end test, October 2026

Scope agreed in the 2026-10-27 review: the Run page for rawat jalan (rajal) and rawat inap (ranap) end to end —
nodes, wording, steps, UI/UX, progress, error handling, slow office PCs and small screens, animation, Fixed/Flexible.

Status: **fixture + fault-injection phase done (checkpoint 1)**. Live preview/write and the wording pass follow.

## How it was tested

| Piece | What |
|---|---|
| QA harness (`apps/orchestrator/src/qaTransport.ts`) | Runs the **real** executors, mutation gate, ledger and SSE against fixtures. On a QA host only (`QA_AUTH_TOKEN`): named scenarios, synthetic rajal batches of any size, per-request latency, injected faults (timeout, network, HTTP 500, login page, dropped cookie). The UI's own "Fixture replay" only plays synthetic events in the browser and never touched any of this. |
| `scripts/qa-run-e2e.mjs` | Opens a QA run in headless Chrome under an office-PC profile; measures time to first progress, long tasks, fps/jank, progress lag vs the server, click latency, heap/DOM, console errors; per-node report and screenshot. |
| `scripts/qa-multitab.mjs` | N tabs watching a running run; times an API call from the last tab. |
| Build | All numbers below are on the **production bundle** served by the orchestrator. The Vite dev server (React development build) was 2–4× slower and is not representative. |

Office-PC profiles (agreed):

| Profile | CPU slowdown | Viewport | Stands for |
|---|---|---|---|
| A | ×1 | 1536×864 (1080p @125%) | i3 gen 12, 8 GB |
| B | ×4 | 1366×768 | i3 gen 10, 4–8 GB |
| C | ×6 | 1093×614 (768p @125%) | older Intel, 4 GB |

Targets: first progress < 2 s · click < 300 ms · no long task > 500 ms · ≥ 30 fps on B · heap < 400 MB · UI not behind the run.
